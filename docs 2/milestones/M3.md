# M3 — Flashcards & SRS Engine (design note)

*Shipped July 2026. Done criteria from `docs/03-roadmap.md`: the complete
learn→review loop works daily and retention data accrues.*

## What shipped

**Scheduler** (`app/services/srs.py`): SM-2 behind a `Scheduler` protocol — pure
function `(SrsState, rating, now) → SrsState`, so FSRS can replace it later without a
data migration. Learning steps (1 min, 10 min) before graduation (1 day; easy = 4 days),
review phase with ease 1.3–3.0, hard = ×1.2 − 0.15 ease, good = ×ease,
easy = ×ease×1.3 + 0.15, lapse = relearning + ease −0.20. 12-test unit battery covers
step walking, graduation, lapse cycles, ease bounds, monotonic growth.

**Schema** (Alembic `a438ed7ebc72`): `decks` (user-owned), `cards` (corpus-word-linked
*or* custom front/back; embedded SRS state; favorite + memory note; unique
user+word), `review_logs` — **append-only**, no FK to cards (history outlives the card),
storing rating, before/after interval and ease, and answer duration for future
retention analytics and FSRS training.

**API** (all Bearer-authed, ownership-checked): decks CRUD; card create (word or
custom), update (favorite/note/move), delete; `POST /cards/add-by-level` — bulk-start
the next N most frequent unlearned words of a CEFR level; `GET /review/queue` — due
cards first (oldest due), then new cards up to a per-session cap (default 10);
`POST /review/{card}` — schedules + appends the log atomically;
`POST /decks/{id}/import` — Quizlet/Anki-style CSV **and** TSV (front/back), duplicate
fronts skipped, bad rows reported; `GET /decks/{id}/export` — CSV download, always
available (the Memrise lesson: your data is yours).

**Web.** `/[lang]/review` — session UI: 3-D flip (Framer Motion, honors
prefers-reduced-motion), swipe right = good / left = again, keyboard (Space flips,
1–4 rate), Again/Hard/Good/Easy buttons with shortcut hints, progress bar, memory-note
editor, session-complete and empty states. `/[lang]/decks` — main corpus deck with due
counter + add-by-level, custom decks (create, import, export, delete). Dashboard hero
now shows today's due count with a Start Review CTA; the review module card is live
with a due badge.

## Decisions & tradeoffs

- **SM-2 with learning steps** rather than pure SM-2 — same-day relearn is what makes
  "Again" non-punishing; pure day-granularity SM-2 frustrates beginners.
- **SRS state embedded on the card** (not a separate table): one row per learnable item,
  no join on the hottest query path. The append-only log is the source of truth for
  history.
- **Card audio & hint fields** land with the media pipeline (M5–M7); `memory_note`
  covers the hint use-case today.
- **Session cap 30 / new 10** are server defaults; per-user settings arrive with the
  Settings page (M4).
- **Web testing**: SM-2 correctness lives server-side (12 unit tests + API flow tests);
  the review UI was verified by live smoke. Playwright e2e for the review loop is the
  first target when e2e lands.
