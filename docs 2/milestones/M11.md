# M11 — Content Scale-out & Four Skills (design note)

*Shipped July 2026. The content half deferred from M10: a materially bigger
corpus plus the listening/reading/writing/speaking sections — turning a
vocabulary trainer into a rounded language-practice platform.*

## What shipped

**Corpus expansion** — three curated trilingual batches through the proven
M2 CSV pipeline: A2 extended (+50), a new **B1 batch (71)** and **B2 batch
(44)** — every entry hand-written with uz/ru translations, learner-graded
definition, IPA, category, and a bilingual example. Published corpus:
354 → **513 words** (A2 108 · B1 71 · B2 44). `seed.py` now iterates
`CORPUS_FILES`, so the next batch is a drop-in CSV.

**Listening & Speaking = game types**, not a parallel system. Two new types in
the M5 session framework (`listening`, `speaking`) draw from the user's own
due/weak cards and feed SRS through the same `/games/answer`:

- **Listening (dictation)** 🎧 — TTS speaks a corpus example sentence; the
  learner types what they hear. Comparison is punctuation-insensitive — nobody
  fails a dictation over a missing full stop.
- **Speaking (pronunciation)** 🗣️ — see the Uzbek word, say the English one;
  the browser's `SpeechRecognition` transcript (5 alternatives) is matched
  against the headword. Where the API doesn't exist (Firefox), the UI falls
  back to honest self-assessment buttons rather than silently breaking.

Both are surfaced under `/skills`, not the games hub — drills, not arcade.

**Reading** 📖 — new `reading_passages` + `reading_questions` tables
(migration `408213cc8563`) and **9 hand-written graded passages** (3 × A1/A2/B1,
Uzbek-context stories — Registan, the bazaar, drip irrigation in the Aral
region) with 3–4 comprehension MCQs each and an optional Uzbek gloss shown
*after* submission. API: list (level filter) / detail / submit. The detail
response **never includes `answer_index`**; grading is server-side. Correct
answers earn **5 XP each** via a new `apply_skill_xp()` — XP that counts toward
level, daily XP, and the weekly league, but deliberately **not** review
streaks/goals, which stay tied to real SRS reviews.

**Writing** ✍️ — a static, versioned prompt bank (A1–B2, editorial content in
code) served from `/skills/writing/prompts`, paired with the existing M6
`/ai/writing-check` for corrected text + feedback. When AI is unconfigured the
page says so and stays usable as a plain writing pad.

**Web** — `/skills` hub + four section pages (all i18n'd uz/ru/en, parity test
passing), 📚 header link, `GamePlayer` gained an `exitPath` so drills return to
`/skills`. The reading view is list → passage → answer → per-question ✓/✗ +
XP; the speaking view is a one-tap mic with live "heard: …" feedback.

## Decisions & tradeoffs

- **Skills reuse the games plumbing.** Listening/speaking are 30 lines of
  session-builder each, get SRS feeding, XP, and anti-cheat for free, and the
  hub/games surface stays uncluttered (they're excluded from `GAME_TYPES` on
  the web side, so `/games/listening` 404s).
- **Server-side grading for reading** — same principle as multiplayer: the
  answer never ships to the client.
- **Skill XP ≠ review XP.** Reading rewards flow through `apply_skill_xp`,
  which feeds level/league but not streaks — streak integrity is the
  anti-anxiety core of M4 and stays strictly review-based.
- **SpeechRecognition needs Chrome/Safari** and usually a network round-trip;
  the self-assessment fallback keeps the drill functional everywhere without
  pretending accuracy we don't have.
- **9 passages, 513 words is a foundation, not the ceiling** — the roadmap's
  ~3k-word target is now purely an authoring cadence (drop-in CSVs, drop-in
  passage JSON), no engineering gate left.
