# M9 — Games Wave 2 + Social (design note)

*Shipped July 2026. The platform becomes multiplayer: five more single-player
games, a friends layer with shareable profiles, and real-time head-to-head quiz.*

## What shipped

**Games wave 2** — five new games on the same M5 framework (session from your due
SRS cards, answers feed `/games/answer`, all randomness happens post-fetch in the
parent's `prepare()` so the game components stay render-pure):

- **Boss Battle** 🐉 — speed-quiz variant; each correct answer chips the boss's HP
  bar down. Pure competition-flavored multiple choice.
- **Hangman** 🪢 — guess the English word letter-by-letter, 6 lives. Duration is
  derived from wrong-guess count (not `Date.now()`) so the mapped letter buttons
  stay pure under the React compiler.
- **Spelling Bee** 🐝 — hear the word (Web Speech), type the spelling; `normalize()`
  comparison.
- **Sentence Builder** 🧩 — tap scrambled word tiles into the correct order;
  restricted to cards that have an example sentence.
- **Word Search** 🔍 — headwords hidden in a letter grid (horizontal / vertical /
  diagonal); grid generated in `buildWordSearch()` during the post-fetch prepare
  step. Each found word feeds SRS once.

**Social layer**:

- **Friendships** (`friendships` table, `requester_id`/`addressee_id`, status
  `pending | accepted`, unique per pair). Add by **friend code** — the reused M7
  `referral_code`, so one identity is the referral link *and* the friend handle.
  Only the addressee can accept/decline; either side can remove.
- **Friends leaderboard** — me + accepted friends ranked by XP, with streaks;
  `is_me` flagged for highlight.
- **Shareable public profiles** (`/profile/{code}`) — display name, level, XP,
  streaks, and earned achievement badges. Copy-link to share.

**Real-time multiplayer quiz** (WebSocket `/ws/quiz`):

- **Room model** — in-memory `RoomManager` with 4-char codes; a host creates,
  others join by code, host picks a CEFR level and starts.
- **Shared questions** — `build_public_quiz()` draws MC questions from the shared
  **published corpus**, not any one player's cards, so everyone sees the same 8
  questions. A round reveals once **every** player has answered; +10 per correct;
  host advances; final scoreboard with medals.
- **Auth over WS** — access token passed as a `?token=` query param and resolved to
  a user before the socket joins a room; disconnect cleans up membership and drops
  empty rooms.

## Decisions & tradeoffs

- **Room logic is decoupled from the socket.** `Room`/`RoomManager` are plain
  classes with no WebSocket import; the endpoint is a thin transport adapter that
  drives a `Room` and broadcasts its messages. That's what makes the lifecycle
  unit-testable (lifecycle+scoring, double-answer ignored, wrong-round ignored,
  case-insensitive lookup) without spinning up a socket.
- **Multiplayer answers do NOT feed SRS.** It's pure competition on a shared
  question set — mixing another player's corpus into your scheduler would be noise.
  Single-player games remain the one true SRS path (the M5 principle).
- **In-memory, single-process rooms.** Correct and simple for launch scale; the
  scale-out path is a Redis pub/sub backplane keyed by room code — the decoupled
  `Room` makes that a transport swap, not a rewrite.
- **Friend code = referral code.** No second identifier to mint, explain, or keep
  in sync; the growth loop and the social loop share one handle.
- **Never leak the answer index.** `current_question()` sends prompt + options only;
  the correct index is revealed server-side after all players answer.
