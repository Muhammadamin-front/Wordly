# M1 — Foundation & Auth (design note)

*Shipped July 2026. Done criteria from `docs/03-roadmap.md`: a user can sign up, verify,
log in, and see a localized dashboard in production config.*

## What shipped

**Monorepo.** npm workspace `apps/web` (Next.js 16) + `apps/api` (FastAPI, Python venv).
Root `docker-compose.yml` (Postgres 16, Redis 7, API container), GitHub Actions CI
(pytest / vitest / eslint / next build).

**API** (`/api/v1`):

| Endpoint | Notes |
|---|---|
| `POST /auth/register` | bcrypt hash, profile created inline, verification email sent, tokens issued |
| `POST /auth/login` | identical 401 for unknown email vs wrong password (no enumeration) |
| `POST /auth/google` | ID-token verify via injectable `GoogleVerifier`; links to existing email account |
| `POST /auth/refresh` | rotating opaque tokens, SHA-256-hashed at rest; **reuse ⇒ revoke all sessions** |
| `POST /auth/logout` | revokes presented token, clears cookie |
| `POST /auth/verify-email`, `/forgot-password`, `/reset-password` | single-use hashed one-time tokens; reset revokes all sessions; forgot always 200 |
| `GET /auth/me`, `PATCH /users/me` | Bearer-authenticated |

Cross-cutting: security headers middleware, CORS locked to `FRONTEND_ORIGIN`, per-scope
rate limiting (Redis fixed-window in prod, in-memory sliding-window fallback), JWT access
tokens (15 min), refresh cookie `httpOnly; SameSite=Lax; path=/api/v1/auth`.

**Schema** (Alembic `c3f22e799dd8`): `users`, `profiles` (1:1), `refresh_tokens`
(append-audit rows with `revoked_at`/`replaced_by_id`), `one_time_tokens`.

**Web.** Locale-prefixed routes (`/uz`, `/ru`, `/en`) via `proxy.ts` (cookie → Accept-Language
detection); dictionary-based i18n with type-checked parity test; design tokens in Tailwind v4
`@theme` (brand indigo / accent turquoise / sand, light+dark with pre-paint init script);
cva-based UI kit (Button/Input/Card/Alert/Label); landing (hero, features, pricing, CTA,
Framer Motion reveals honoring `prefers-reduced-motion`); auth pages under `/[lang]/auth/*`
matching API email links; client dashboard with silent-refresh session bootstrap
(access token in memory only, never storage).

## Decisions & tradeoffs

- **Python 3.9 compatibility** (dev machine): `typing.Optional` style throughout; prod
  container runs 3.12.
- **Login allowed before email verification** — dashboard shows a verify banner instead of
  blocking; conversion-friendly, revisit for sensitive features.
- **Google button** renders only when `NEXT_PUBLIC_GOOGLE_CLIENT_ID` is set; server verifies
  via tokeninfo (swap to offline JWKS verification when traffic justifies it).
- **Email backend is console/outbox** — real SMTP/provider lands with production infra (M7).
- **E2E deferred**: web coverage is vitest component/i18n tests + a manual end-to-end smoke
  (register → login → /me → localized pages, performed at ship time). Playwright arrives in M2
  when there are learner flows worth scripting.
- **Naive-UTC datetimes** everywhere (documented in `core/security.utcnow`) — portable across
  SQLite/Postgres without tz-aware comparison bugs.
