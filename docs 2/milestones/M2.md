# M2 — Vocabulary Core & Content Pipeline (design note)

*Shipped July 2026. Done criteria from `docs/03-roadmap.md`: the A1 corpus is
browsable, searchable, and admin-manageable.*

## What shipped

**Schema** (Alembic `e00cbb24d9dd`): `categories` (trilingual names + emoji),
`words` (headword, SEO slug, POS, IPA, CEFR level, frequency rank, word family,
common-mistake note, draft→review→published status), `word_senses` (EN definition +
uz/ru translations, multiple senses supported), `word_examples` (EN/UZ/RU + audio slot),
`word_relations` (synonym/antonym/collocation/phrasal-verb; auto-links to a corpus word
when one exists, plain text otherwise).

**API.** Public: `GET /categories`, `GET /words` (level/category/search filters +
pagination; search matches headword **and** uz/ru translations; only `published`
visible), `GET /words/{slug}`. Admin (role-guarded): full CRUD, status workflow,
`POST /admin/words/import` — CSV with per-row SAVEPOINT error isolation, upsert by
(headword, pos) slug, per-line error report.

**Content.** `scripts/data/a1_corpus.csv`: **306 A1 words** across 16 categories, each
with IPA, Uzbek + Russian translation, learner-graded English definition, an EN example
with Uzbek translation, frequency rank, and synonym/antonym links. `scripts/seed.py`
is idempotent (re-run = update, not duplicate) and dogfoods the admin CSV importer.
`scripts/make_admin.py <email>` promotes an admin.

**Web.** `/[lang]/vocabulary` — SSR browser with level tabs, category chips, plain-GET
search (works without JS, crawlable); `/[lang]/words/[slug]` — SEO word page (title =
"apple — olma"); admin CMS at `/[lang]/admin/words` (status-filtered table, search,
CSV upload with import report, delete) + create/edit form; dashboard Vocabulary card
is now live.

## Decisions & tradeoffs

- **One sense per word in the CSV/admin form** for M2 — the schema and API accept
  multiple senses; the form UI grows when B1+ polysemy actually needs it.
- **Frequency ranks are curated approximations** for ordering, not corpus-derived;
  replace with real COCA/SUBTLEX ranks during content scale-out (M10).
- **LIKE-based search** — right for 306 rows; swap to Postgres trigram/FTS behind the
  same service function when the corpus grows.
- **No audio/images yet** — schema slots exist (`audio_url`, `image_url`); recording
  pipeline is scheduled with media infra (M5–M7).
- **Admin edit fetches client-side** (Bearer token lives in browser memory), while
  public pages render server-side for SEO.
