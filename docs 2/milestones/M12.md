# M12 — Production Readiness (design note)

*Shipped July 2026. Everything between "works on my machine" and "deployable":
the production database validated for real, both apps containerized, CI gating
dialect drift, and a deploy guide.*

## What shipped

**Postgres validated end-to-end — for the first time.** Dev and tests had run
on SQLite since M1; production was always going to be Postgres, untested. Now:

- All **9 migrations** apply cleanly to Postgres 16 (`alembic upgrade head`).
- The **full 173-test suite passes against Postgres** — the fixture honours
  `TEST_DATABASE_URL` and drop/creates per test for isolation on a shared
  server DB (still defaults to in-memory SQLite for speed).
- Seed loads the 609-word corpus + 9 passages; the API boots against
  Postgres + Redis with `health/detail` reporting `backend: redis`, and the
  **RedisCache / RedisStorage backends served live traffic** (cache MISS→HIT
  over Redis) — also a first; they had existed since M1/M10 untested.

**Repo bug fixed: the npm workspace was silently broken.** The root
`package.json` had been committed as literally `package 2.json` (a Finder
duplicate slipped into M4). Every workspace command — and the **CI web job —
had been failing ever since**; local work papered over it by running tools from
`apps/web` directly, which also spawned a stray second lockfile and Next's
multi-lockfile warning. Renamed back, lockfile reconciled from root, stray
`apps/web/package-lock.json` removed, workspace commands verified.

**Web containerized** (`apps/web/Dockerfile`): Next.js `output: "standalone"`
(with `outputFileTracingRoot` at the monorepo root) in a 3-stage build →
non-root runtime image, 269 MB. One gotcha worth recording: npm's workspace
`ci` skips platform-specific optional deps when the lockfile was written on
another OS (npm/cli#4828) — Tailwind v4's native `lightningcss` /
`@tailwindcss/oxide` musl bindings must be reinstalled in the build stage.

**Compose is now the whole product**: postgres + redis + api (with a
`/health/detail` healthcheck gating web startup) + web. Host port overridable
via `POSTGRES_PORT` for machines with a local Postgres. Verified live: all
four containers healthy, seed idempotent inside the api container, `/uz` 200
from the web container, register→token roundtrip through the containerized API.

**CI hardened** (`.github/workflows/ci.yml`): the existing SQLite pytest job is
joined by an **API-on-Postgres job** — a `postgres:16-alpine` service container
running the same 173 tests plus `alembic upgrade head` + seed in a separate
database (the test fixture's `create_all` would collide with alembic in one) —
and the web job gains `tsc --noEmit`.

**Deploy guide** (`docs/deploy.md`): env vars that bite (`SECRET_KEY` boot
refusal, `NEXT_PUBLIC_*` being build-time), TLS/proxy requirements (WebSocket
upgrade for `/ws/quiz`, `X-Forwarded-For` for rate limiting), health probes,
backup story (Postgres is all durable state; Redis is disposable; multiplayer
rooms are in-process and drop on deploy), single-API-replica constraint until
the Redis backplane lands.

## Decisions & tradeoffs

- **Tests default to SQLite, CI runs both.** SQLite keeps the edit-test loop at
  ~1 min; the Postgres job (~1.5 min, parallel) catches dialect drift where it
  belongs — in CI, not on the VM.
- **`NEXT_PUBLIC_API_URL` as build arg** — Next.js inlines it into the client
  bundle; pretending it's a runtime env var is a footgun, so compose passes it
  to `build.args` explicitly.
- **One compose file**, not a `-prod` variant: the same topology serves both,
  with production toggled by env (`ENVIRONMENT`, `COOKIE_SECURE`, real keys).
  Fewer files to drift apart.
- **Single API replica documented as a constraint**, not hidden: multiplayer
  rooms are in-process by design (M9); the scale-out path is a transport swap.

## Verified at ship time

- Postgres 16 (container): 9/9 migrations, **pytest 173/173**, seed, live API
  smoke with Redis cache HIT and register→token.
- SQLite path unchanged: 173/173.
- `docker compose config` valid; api + web images build; full 4-container

- Workspace restored: `npm run test/lint/build --workspace web` green from
