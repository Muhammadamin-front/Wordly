# M10 — Performance & Hardening (design note)

*Shipped July 2026. The final roadmap milestone. Scoped to the **engineering**
half of "Content scale-out, Performance & Hardening" — caching, rate-limit
coverage, observability, error hardening, and load testing — plus a modest,
honest corpus increment. Full A2–B2 authoring (≈3k words) and the
listening/reading/writing/speaking sections remain tracked content work; the
pipeline shipped here (CSV import from M2, multi-file seed) is what makes that a
content task rather than an engineering one.*

## What shipped

**Response cache** (`app/core/cache.py`) — same two-backend shape as the
rate-limiter: a `Cache` Protocol with `MemoryCache` (process-local TTL) for
dev/single-process and `RedisCache` for production, selected in the app lifespan.
`cached_response()` serves the hot, **user-agnostic** public reads — corpus
browse (`/words`), `/categories`, and word detail (`/words/{slug}`) — with
`Cache-Control`, an `ETag`, an `X-Cache: HIT|MISS` marker, and `If-None-Match` →
`304` support. Only *published* corpus data is ever cached, so there is no
per-user leakage; staleness after an admin edit is bounded by the TTL
(categories 300s, browse 60s, detail 120s).

**Rate-limit coverage** — the M1 limiter (sliding-window memory / fixed-window
Redis) previously guarded only auth + flashcards. Now applied at router level to
the expensive/abusable surfaces: **AI** (20/60 — tokens + latency cost), **games**
(90/60), **social** (30/60), and **multiplayer room creation** (20/60, enforced
by client IP inside the WebSocket `create` handler). All tunable via config.

**Observability** — a single `http` middleware assigns/propagates an
`X-Request-ID` (honouring an inbound one for distributed tracing), times every
request, emits a structured log line (with a **slow-request warning** above
`SLOW_REQUEST_MS`), and sets `X-Response-Time-ms` plus the security headers.
`GET /health` stays a cheap liveness probe; new **`GET /health/detail`** is a
readiness probe — pings the DB (`SELECT 1`) and reports version, environment,
uptime, and the active cache/limiter backend.

**Error & payload hardening** — the same middleware is the last-resort handler:
unhandled exceptions are logged **with the request ID** and returned as a generic
`500 {"detail": "Internal server error"}` — no stack traces or internals leak to
clients. A declared-`Content-Length` guard rejects oversized bodies with `413`
before they hit a route. `Strict-Transport-Security` is sent in production.

**Load test** (`scripts/loadtest.py`) — a hand-run async hammer of the anonymous
read path reporting p50/p95/p99, RPS, and the cache HIT ratio. Not in CI.

**Content** — an honest **A2 batch** (58 curated trilingual entries with IPA and
examples, `scripts/data/a2_corpus.csv`); `seed.py` now loads every file in
`CORPUS_FILES`, so future CEFR levels are a drop-in CSV. Published corpus: 306 →
**354** words.

## Decisions & tradeoffs

- **Cache keyed on published data only, short TTLs, no active invalidation.**
  Admin edits become visible within one TTL rather than instantly — the honest
  trade for a dependency-free cache. Explicit invalidation (bump a version key on
  write) is a clean follow-up if editors need immediacy.
- **Content-Length guard, not full stream metering.** Cheap and stops obvious
  abuse; true byte-metering of a streamed body belongs at the reverse proxy /
  ingress, which is where the 5 MB cap should also live in prod.
- **Multiplayer limiter lives in the WS handler**, not a router dependency — the
  action is a socket message, not an HTTP call, so the limiter storage is invoked
  directly by client IP.
- **Scoped to engineering, per the milestone decision.** Rather than pad the
  corpus to 3k programmatically-generated (lower-quality) entries, M10 ships the
  seed/import pipeline proven at a larger level and a small high-quality batch;
  bulk authoring and the LRWS skill sections are the next content milestone.

## Verified at ship time

- `pytest`: **153 passed** (11 new) — request-ID present/preserved, `/health/detail`
  db+build, cache `Cache-Control`/`ETag`/`304`/`X-Cache` HIT-then-MISS, sliding
  window limiter, router 429 after limit, `413` on oversized body, and a masked
  `500` that leaks no internals but keeps the request ID.
- Seed loads A1+A2 cleanly (48 created, 10 overlaps upgraded); `/words?level=A2`
  returns 58.
- Live smoke (running server): `/health/detail` ok; `/words` returned
  `Cache-Control`, `ETag`, `X-Request-ID`, `X-Response-Time-ms`, `X-Cache: MISS`
  then `HIT`, and a conditional request got `304`.
- `scripts/loadtest.py` (1500 req / 40 concurrent): **736 req/s**, all 200,
  p50 46 ms / p95 66 ms, **cache HIT ≈ 96%** of cacheable requests.

## Roadmap status

M10 closes the numbered roadmap. Remaining before GA is **content production**
(A2–B2 corpus to ~3k words, LRWS skill sections) — feature-flag new surfaces as
they land — on top of the hardened, observable platform shipped here.
