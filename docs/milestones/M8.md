# M8 — Teacher & Admin Panels (design note)

*Shipped July 2026. Done criteria from `docs/03-roadmap.md`: a teacher can run a
30-pupil class for a week without touching us.*

## What shipped

**Teacher panel — the distribution channel** (the thesis from the market research:
one teacher brings 120 students):

- **Classes** (`classrooms` table): create with a 6-char join code (unambiguous
  alphabet); creating your first class **auto-promotes you to teacher** — no approval
  gate, deliberately frictionless. Archive supported.
- **Join flow** (`class_memberships`): students enter the code (`/classes/join`, or
  the 🎒 page); duplicate joins are idempotent, invalid codes 404.
- **Assignments** (`assignments`): title, instructions, a target review count, and a
  deadline. **Progress is measured from the SRS review log** — reviews done since the
  assignment was created count toward the target, so homework *is* real studying,
  not a parallel busywork system (the same "one path" principle as games in M5).
- **Class analytics**: per-student level/streak/total reviews and per-assignment
  completion (n of m students done), sized for a ~30-seat class.
- **Student view**: my classes, join form, per-assignment progress with done/overdue
  badges.

**Admin panel** (`/admin`, role-gated):

- **Analytics**: users, premium users, active subscriptions, revenue (from performed
  payments, in so'm), open AI reports, total reviews.
- **AI-report moderation**: the queue fed by M6's one-tap reporting — open/resolved
  lists, one-click resolve. Closes the trust loop promised in the research.
- **User management**: search, ban/unban (`is_active=false` blocks login *and* every
  authenticated call via the existing `get_current_user` check), role changes
  (learner/teacher/admin), self-modification blocked.
- Links to the existing words CMS (M2).

## Decisions & tradeoffs

- **Assignment progress = review-log count since assignment creation.** Simple, honest,
  and impossible to game without actually studying. Per-deck or per-word-list
  assignments can layer on later; the schema doesn't preclude them.
- **First class promotes to teacher** rather than an application flow — teachers are
  the growth channel; friction there is friction on growth. Admin can demote via the
  role control if abused.
- **Analytics loops per student/assignment** (N+1-ish) — correct and fine at 30 seats;
  batch queries are a known optimization when School Plan classes get big.
- **No School Plan billing wiring yet** — classes are free (they drive acquisition);
  per-classroom licensing hooks into the M7 plans table when B2B sales start.
