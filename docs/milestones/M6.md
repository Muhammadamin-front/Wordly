# M6 — AI Tutor (design note)

*Shipped July 2026. Done criteria from `docs/03-roadmap.md`: free users get 5
useful AI actions/day with quotas enforced server-side.*

## What shipped

**AI client** (`app/services/ai_client.py`): a thin `AiClient` protocol over the
Anthropic SDK's `AsyncAnthropic`. Model is `claude-opus-4-8` (configurable via
`AI_MODEL`). Three primitives — `text`, `chat`, `json` (structured via
`output_config.format`). **Extended thinking is intentionally off**: these are short
generation tasks where latency and cost beat deep reasoning. The whole feature
**degrades gracefully** — when `ANTHROPIC_API_KEY` is unset, `get_ai_client()` returns
`None` and every generation endpoint returns 503 while quota/report still work, so the
app runs with no key.

**Endpoints** (`/ai/*`, all auth'd):
- `explain` — word explanation in the learner's UI language, with an Uzbek-learner
  mistake note.
- `mnemonic` — a memory hook for a word.
- `story` — a mini-story that weaves in the user's due/learning words (or given words).
- `quiz` — structured multiple-choice questions (JSON schema output).
- `chat` — conversation practice; the system prompt is **level-adapted** (A1–C2), the
  Memrise failure mode we called out in research.
- `writing-check` — corrected text + short feedback (structured).
- `quota` — remaining actions today; `report` — flag any AI output for teacher review.

**Quota** (`app/services/ai_quota.py` + `ai_usage` table): one row per user per local
day, incremented **only after a successful model call** so failed generations don't
cost a slot. Free tier = 5/day (`AI_FREE_DAILY_QUOTA`); enforced server-side with a 429.
Plan-based quotas slot in at M7 — `daily_quota()` is the single hook.

**Trust** (the Knowt/Memrise lesson): every AI response carries `ai_generated: true`,
the UI labels it "✨ AI-generated", and one tap files an `AiReport` for the M8
moderation queue. Core corpus stays human-curated; AI is supplementary and clearly
marked.

**Web**: `/[lang]/ai` AI Tutor (Chat + Writing-check tabs, level picker, live quota
pill, graceful "unavailable" state); an inline "✨ Explain with AI / 🧠 Memory hook"
panel on every word page with a report link; header ✨ and a dashboard AI card.

## Decisions & tradeoffs

- **`claude-opus-4-8` default, no thinking.** Best-quality model per the claude-api
  skill's guidance; thinking omitted for latency/cost on simple generation. The model
  is one config line to change for cost-tuning at scale.
- **Provider-agnostic seam.** Endpoints depend on the `AiClient` protocol, so tests
  inject a deterministic fake — no key, no network — and a different provider could be
  dropped in behind the same interface.
- **Structured outputs** for quiz + writing-check via `output_config.format` (documented
  raw form) rather than prompt-and-hope JSON.
- **Quota in Postgres, not Redis** — same call as M4 leagues: correct and testable now;
  a Redis counter is a scale optimization.
- **No streaming yet** — replies are short (2–3 sentences / <70 words), so a single
  response is fine; streaming chat can come with native mobile.

- `pytest`: **99 passed** (10 new) — quota defaults, 503 when unconfigured, labeled text
  + quota consumption, quota 429 after the limit, level-adapted chat, structured quiz,
  writing-check, story-needs-3-words, report persisted. AI tests inject a fake client
  (no key/network).
- `vitest` 6 passed; tsc clean; eslint clean; `next build` clean (72 pages).
- Live smoke (no key configured — the realistic default): `/ai/quota` →
  `{remaining:5, enabled:false}`, `/ai/explain` → 503, `/ai/report` → 201; `/uz/ai` and
  word pages return 200.
