# M4 — Gamification (design note)

*Shipped July 2026. Done criteria from `docs/03-roadmap.md`: the core loop has
visible progression and a weekly league runs end-to-end.*

## What shipped

**Economy & leveling** (`app/services/leveling.py`, pure/tested): XP per review
(again 4 → easy 12), 1 coin per review, level curve where level L→L+1 costs
100 + (L−1)×20 XP. Daily-goal completion bonus (+20 XP, +10 coins). All constants
in one module; `level_progress(xp) → (level, into, needed)` drives the UI bars.

**Streaks — anti-anxiety by design** (the Duolingo complaint from research): a
missed day is covered automatically by a **streak freeze** if you own one (start with
2); freezes only trigger on a single missed day, so life doesn't nuke a 47-day streak.
Freezes are earned/bought with coins (50 each, max 5). `longest_streak` preserved.

**Daily activity** (`daily_activity` table, one row per local day): reviews + XP +
goal-reached flag. Also the durable substrate for the M5 statistics heatmap. Local day
computed from the user's profile timezone (Asia/Tashkent default).

**Achievements** (`app/services/achievements.py`): 11 badges across volume / streak /
mastery / level / goal, each with XP + coin rewards and a pure unlock predicate. Codes
+ rewards live in the backend; titles/descriptions/icons live in the web dictionaries
(i18n). Checked after every review; the "mastered words" query only runs while a
mastery badge is still locked.

**Weekly leagues** (`app/services/leagues.py`): Duolingo-style tiers (bronze → pearl),
groups of 30, top 7 promote / bottom 5 relegate. Backed by the `league_entries` table
(durable, testable) — **promotion/relegation is computed lazily** when a user's first
activity of a new week creates their entry, ranking the previous week's finish. No cron
needed. (A Redis sorted-set fast path is a documented future optimization; the DB
implementation is correct and indexed for now.)

**Integration**: the review endpoint now runs `apply_review_rewards` inside the same
transaction as the SRS update + review-log append, and returns a `reward` object
(XP/coins/level-up/streak/freeze/goal/new-achievements) so the UI can react instantly.

**API**: `GET /me/stats`, `PUT /me/daily-goal`, `POST /me/streak-freeze`,
`GET /me/achievements`, `GET /me/heatmap`, `GET /leaderboard`.

**Web**: header stats pill (🔥 streak · ⚡ level · 🪙 coins, live-refreshing via a
`words:stats-changed` event); dashboard stats strip + daily-goal progress and picker;
achievements page (level/XP summary + badge grid, locked badges grayscaled);
leaderboard page (tier, ranked group, promotion/relegation zones, "you" highlight);
in-session reward toasts (level-up, achievement, freeze-saved, goal-reached, +XP) and a
session-summary card (+XP total, badges earned).

## Decisions & tradeoffs

- **Rewards are server-authoritative** — the client only displays what the API returns,
  so XP can't be forged from the browser.
- **Leagues on Postgres, not Redis** — correctness and testability first; the sorted-set
  cache is a scale optimization deferred until it matters. Documented, not half-built.
- **Streak freeze auto-consumes** rather than requiring a manual "repair" — fewer taps,
  less anxiety; a coin-purchase repair flow can come later if data shows demand.
- **Lazy league entry / stats creation** — no registration backfill migration; a user's
  gamification rows appear on first stats read or first review.
